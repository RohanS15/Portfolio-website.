# Portfolio GitHub, EmailJS, and Vercel setup

**Updated:** 10 November 2026
**Flow:** local project → EmailJS setup → GitHub → Vercel

This is a setup guide, not a record that accounts have been created or that deployment has happened. The contact form uses EmailJS in the browser; it does not need a Resend API, a Vercel Function, or a custom domain.

## Current project setup

- React, TypeScript, Vite, and npm; `package-lock.json` is the dependency lockfile.
- Routes: `/`, `/portfolio`, `/projects`, and `/playground`.
- Contact UI and client-side validation are in `src/components/contact/ContactForm.tsx` and `validateContact.ts`.
- Email sending is handled by `src/components/contact/emailjsClient.ts` with `@emailjs/browser`.
- Required build-time public configuration: `VITE_EMAILJS_SERVICE_ID`, `VITE_EMAILJS_TEMPLATE_ID`, and `VITE_EMAILJS_PUBLIC_KEY`.
- `.env.example` has placeholders. Copy it to `.env.local` and fill in the identifiers from the EmailJS dashboard for local work. `.env.local` is ignored by Git.
- `vercel.json` rewrites app routes to the SPA entry point. The EmailJS form sends directly to EmailJS, so Vercel does not need an API function for contact mail.
- The project folder must be initialized as a Git repository before GitHub can deploy it.

## 1. Set up EmailJS

1. Create an EmailJS account.
2. In **Email Services**, connect the inbox where portfolio inquiries should arrive (for example, Gmail). A personal inbox is suitable for a low-volume portfolio; the email provider's own sending limits still apply.
3. Send a test email from EmailJS and confirm it arrives.
4. Create a template with variables `{{name}}`, `{{email}}`, `{{subject}}`, and `{{message}}`.
5. Set the template's **To Email** to the portfolio owner's inbox and **Reply-To** to `{{email}}`. Keep the destination fixed in the dashboard; never accept the destination address from the public form.
6. Copy the EmailJS Service ID, Template ID, and Public Key into local `.env.local` using the names in `.env.example`.
7. Run `npm run dev` and make a real test submission. Confirm arrival in the configured inbox and that replying targets the visitor's address.

The EmailJS public key and service/template IDs are intended for browser use. Never put an EmailJS private key, Gmail password, OAuth token, or another secret in `VITE_` variables. EmailJS documents built-in IP-based rate limits; enable available abuse protections in its dashboard. The existing honeypot only filters simple bots and is not a security boundary. Enable CAPTCHA only after its widget/token integration is implemented and configured in the EmailJS template.

The EmailJS free plan currently lists 200 requests per month. Check the EmailJS dashboard for the current quota before launch.

## 2. Build locally

Run these commands in the project root:

```powershell
npm ci
npm run build
npm run preview
```

Use the preview URL printed in the terminal to open the production build. Check that the form's configuration error appears if `.env.local` is missing, and that a configured test submission produces the correct success or retryable failure state. The project has no lint or automated test script.

## 3. Push the project to GitHub

Create an empty GitHub repository first (no README, license, or `.gitignore` generated by GitHub). From the project root:

```powershell
git init -b main
git add -A
git status --short
git diff --cached --check
git diff --cached --stat
```

Review the staged files. `.env.local`, actual credentials, `node_modules/`, and `dist/` must not be staged. `.env.example` is safe because it contains placeholders. Then commit and push:

```powershell
git commit -m "Prepare portfolio for launch"
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

Replace the remote URL with the HTTPS URL shown by GitHub. If `origin` already exists, inspect it before changing anything. Do not force-push.

## 4. Deploy to Vercel

1. Sign in to Vercel and connect the GitHub account that owns the repository.
2. Choose **New Project** and import the portfolio repository.
3. Use the repository root with Vite, install command `npm ci`, build command `npm run build`, output directory `dist`, and production branch `main`.
4. In **Project → Settings → Environment Variables**, add `VITE_EMAILJS_SERVICE_ID`, `VITE_EMAILJS_TEMPLATE_ID`, and `VITE_EMAILJS_PUBLIC_KEY` for **Production**. Use the same values as the successful local setup.
5. Deploy or redeploy after adding the variables. Vite embeds these public values when it builds the site.
6. Open the generated `*.vercel.app` address and submit one test message. Verify inbox delivery and Reply-To.
7. Open and refresh `/`, `/portfolio`, `/projects`, and `/playground` directly. `vercel.json` provides the SPA fallback.

Vercel provides a `vercel.app` address, so no paid domain is needed to publish this portfolio. A custom domain is optional.

## Go-live checklist

- [ ] EmailJS service is connected to the intended inbox.
- [ ] EmailJS template has the four expected variables, a fixed recipient, and Reply-To set to `{{email}}`.
- [ ] Local test arrives and replies go to the visitor's address.
- [ ] `.env.local` is not committed; only public EmailJS identifiers are configured in Vercel.
- [ ] GitHub `main` is pushed and Vercel has a successful production deployment.
- [ ] Live contact form test arrives in the inbox.
- [ ] Direct route refreshes work on the Vercel address.
- [ ] EmailJS quota and abuse controls are understood before sharing the form publicly.
